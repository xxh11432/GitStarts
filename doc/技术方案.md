基于 **Java + Next.js + MySQL + 云服务器（无域名，IP 直访）**，下面是完整方案。

## 一、最终技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Java 17 + Spring Boot 3.2 | 主流稳定，生态完善 |
| ORM | MyBatis-Plus 3.5 | 对 MySQL 友好，复杂查询/分页灵活 |
| 采集引擎 | Spring `@Scheduled` + 线程池 + Redis 分布式锁 | 定时/并发采集，多实例不重复跑 |
| 数据库 | MySQL 8.0 | 全文检索 + JSON 字段 |
| 缓存/锁 | Redis 7 | 热点缓存 + 分布式锁 + 限流计数 |
| 前端 | Next.js 14 (App Router) + TypeScript + Tailwind | SSR 利于 SEO，排行榜可静态生成 |
| 反向代理 | Nginx | 监听 80（无域名，IP 直访），静态缓存、gzip |
| 部署 | Docker Compose | 一键编排，云服务器单机可跑 |

## 三、数据库表结构（MySQL）

```sql
repositories           -- 仓库主表
  id BIGINT PK AUTO_INCREMENT
  full_name VARCHAR(255) UNIQUE     -- "owner/repo"
  name / owner / description / homepage
  language VARCHAR(64)
  license VARCHAR(64)
  stars INT / forks INT / watchers INT / open_issues INT
  topics JSON                        -- 标签数组
  category VARCHAR(64)               -- 分类（由规则推导）
  default_branch VARCHAR(64)
  pushed_at / created_at DATETIME
  archived / disabled TINYINT
  synced_at DATETIME
  INDEX idx_stars(stars), idx_language(language), idx_category(category)

tags                   -- 标签表
  id BIGINT PK, name, slug UNIQUE, type(ENUM: category|language|topic)

repo_tags              -- 仓库-标签关联
  repo_id, tag_id, PRIMARY KEY(repo_id, tag_id)

sync_logs              -- 采集日志
  id BIGINT PK
  job_type VARCHAR(32)          -- full_sync / incremental / language
  started_at / finished_at DATETIME
  status ENUM('running','success','failed')
  total / succeeded / failed INT
  error_detail TEXT
```

## 五、采集引擎设计（关键）

GitHub 限流是核心约束：**Search API 认证 30 次/分钟，REST 认证 5000 次/小时**。

- **任务类型**
    - `full_sync`：首次全量初始化，按 star 分页拉取热门仓库（排序条件 `sort=stars`）
    - `incremental`：定时（如每小时）更新已收录仓库的最新 star/fork 数据
    - `language`：按主要语言（如 Top 20 语言）分别拉取，保证覆盖度
- **限流**：令牌桶控制 Search 请求 ≤ 25 次/分钟（留 5 次余量），REST 请求走并发线程池
- **并发**：固定线程池（如 8 线程），失败重试 + 指数退避
- **去重/幂等**：Redis 分布式锁（`sync:lock`）保证多实例部署时只有一个实例在跑全量
- **可观测**：每次任务写入 `sync_logs`，记录成功/失败数

## 六、部署方案（云服务器，无域名）

1. 服务器装 Docker + Docker Compose
2. `git clone` 项目 → 配置 `.env`（MySQL 密码、GitHub Token、Redis 密码）
3. `docker compose up -d --build`
4. Nginx 监听 **80 端口**，直接 `` 访问（后续有域名再加 443/SSL）

```yaml
# docker-compose.yml 服务清单
services:
  nginx      # 80，反代 frontend + backend
  frontend   # Next.js
  backend    # Spring Boot
  mysql      # 数据卷持久化
  redis      # 缓存 + 锁
```

## 七、分 6 阶段执行计划

| 阶段 | 内容 | 交付物 |
|---|---|---|
| 1 基础设施 | monorepo、Docker Compose、MySQL 建表、`.env` | 项目能 `docker compose up` 跑通空服务 |
| 2 采集引擎 | GitHub 客户端、限流、定时任务、增量同步 | MySQL 里能自动灌入热门仓库数据 |
| 3 后端 API | 列表/详情/榜单/元数据接口 + Redis 缓存 | 可 curl 调用返回 JSON |
| 4 前端 | 首页榜单、列表（搜索/筛选/排序）、详情页 | 完整可浏览的聚合站 |
| 5 分类体系 | tags 分类规则、语言聚合、榜单计算 | 分类/语言维度可筛选 |
| 6 联调上线 | Nginx 反代、前后端联调、部署到云服务器 | IP 直访可用的线上站点 |
